GROUP B

ตาราง mirror จาก SAP (sync เป็นรอบ)

เก็บไว้เพื่อให้หน้าค้นหา MATNR เร็วและใช้งานได้แม้ service ช้า — ราคาและสต็อกที่ใช้ตัดสินใจจริงต้องยิงสดตอนกดเช็คสต็อก

มีฟังก์ชันเช็คสต็อกของ SAP อยู่แล้ว ยังต้องเก็บไหม?

ไม่ต้องเก็บเป็น “ตัวจริง” — SAP เป็นเจ้าของจำนวนสต็อกเสมอ แต่ยังต้องมีที่เก็บ 3 อย่างฝั่งเรา:

1. cache ระยะสั้น (stock_cache) — เพื่อให้หน้าค้นหาโชว์ “มีของ/หมด” ได้ทันทีโดยไม่ยิง SAP ทุก keystroke เก็บ fetched_at ไว้โชว์ว่าข้อมูลเก่ากี่นาที และตั้ง TTL 5–15 นาที 2. log การเช็ค (stock_checks) — บันทึกทุกครั้งที่เซลล์กดเช็ค: ใครเช็ค แมทไหน SAP ตอบเท่าไร เวลาไหน ใช้ตอนลูกค้าเคลมว่า “ตอนนั้นบอกว่ามีของ” 3. snapshot ในตะกร้า/ใบเสนอราคา — ตอนลงตะกร้าเก็บ plant ที่จะจ่ายของ + atp_date ที่ SAP ตอบมา เพื่อให้ใบเสนอราคายืนยันวันส่งได้ แม้สต็อกเปลี่ยนภายหลัง

กฎ: ปุ่ม “เช็คสต็อก” และตอนกดสร้าง Quotation ต้องยิง SAP สดทุกครั้ง (ห้ามใช้ cache) — cache ใช้แค่ตอนแสดงผลรายการค้นหา

GROUP C

ประวัติการใช้งาน · ประวัติซื้อ · สินค้าขายดี

แยกเป็น 2 ชั้น: ชั้นดิบ (events) เก็บทุกการกดแบบละเอียด และ ชั้นสรุป (rollup) ที่คำนวณรายวันไว้ล่วงหน้า เพราะถ้าคิวรีสินค้าขายดีจาก event ดิบทุกครั้งหน้าเว็บจะช้า

cart_item_historyประวัติการใส่/ลบ/แก้จำนวนของทุกตะกร้า: cart_id, matnr, action (add/update/remove), qty_before, qty_after, added_by (customer/sales), actor_user_id, created_atดิบ · ถาวร (ใช้ตรวจย้อนหลัง)
